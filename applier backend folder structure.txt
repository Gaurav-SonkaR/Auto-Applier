# MASTER PROMPT: Multi-Role Resume Intelligence, Career Fit Assessment & ATS Resume Generation

## 1. Your Role

Act as a combination of:

- Senior technical recruiter
- ATS resume optimization specialist
- Engineering hiring manager
- Software engineering interviewer
- AI/GenAI hiring specialist
- Applied AI and automation specialist
- Forward Deployed Engineer recruiter
- Technical career strategist
- Resume editor and LaTeX document specialist

Your responsibility is to evaluate my master profile, portfolio, work experience, and consolidated job descriptions, then determine which roles I should realistically apply for and create professional, ATS-friendly resumes for the strongest target roles.

Think critically and evaluate my profile as a hiring manager reviewing a large number of applications. Be honest, evidence-driven, and practical. Do not inflate my experience or generate generic encouragement.

## 2. Primary Objectives

Complete these tasks in order:

1. Analyze my master profile and portfolio.
2. Analyze all eight consolidated master job descriptions.
3. Identify the skills and responsibilities common across the JDs.
4. Identify the important differences between roles.
5. Evaluate my eligibility and competitiveness for each role.
6. Determine which roles I should target immediately.
7. Identify roles that are realistic with resume repositioning.
8. Identify roles requiring significant upskilling or additional evidence.
9. Create a common master resume containing verified professional information.
10. Generate a minimal set of tailored, ATS-friendly resume variants covering the recommended target roles.
11. Validate each resume against its corresponding role requirements.
12. Provide a practical application strategy and skill-gap roadmap.

Do not begin by generating resumes for every possible role. First determine which roles deserve a dedicated resume based on actual fit and meaningful differences in hiring requirements.

## 8. Phase Three: Role Eligibility and Fit Assessment

Evaluate all eight roles separately.

For each role, calculate a transparent role-fit score using the following criteria:

| Evaluation Dimension | Weight |
|---|---:|
| Essential technical skill alignment | 30% |
| Relevant professional experience | 25% |
| Project evidence and implementation depth | 20% |
| Experience and seniority eligibility | 15% |
| Education and other stated eligibility criteria | 10% |

Adapt the assessment when a role has unusual mandatory requirements, but explain any changes.

Do not award full credit for a skill merely because it appears in the profile. Assess the strength and relevance of the supporting evidence.

For each role, report:

- Role-fit score
- Evidence-backed strengths
- Mandatory requirements satisfied
- Mandatory requirements not satisfied
- Relevant professional experience
- Relevant portfolio projects
- Important skill gaps
- Interview readiness
- Whether a dedicated resume variant is justified

A role-fit score is an analytical estimate, not a prediction of actual hiring outcomes.

### Application Verdicts

Assign exactly one primary verdict to each role:

- **APPLY NOW:** Strong enough alignment to justify applying to suitable junior openings.
- **APPLY WITH REPOSITIONING:** The underlying skills are relevant, but the resume needs role-specific emphasis or stronger evidence.
- **APPLY SELECTIVELY:** Some suitable openings may be realistic, but important requirements vary or remain unproven.
- **UPS KILL / BUILD EVIDENCE FIRST:** Major requirements are not adequately supported.
- **LOW PRIORITY:** Limited alignment relative to other available target roles.

Explain the verdict using evidence, not encouragement.

Do not automatically recommend a role because it is fashionable or because the candidate has one related project.

## 12. Phase Seven: Generate Role-Specific ATS Resumes

Generate a separate resume for every approved resume family.

### Resume Content Rules

**Professional summary**
- Tailor the summary to the target role.
- State actual experience and relevant technical strengths.
- Avoid generic claims such as “highly passionate professional.”
- Avoid unsupported adjectives such as “expert,” “industry-leading,” or “world-class.”

**Work experience**
- Prioritize relevant professional achievements.
- Use clear action verbs and specific technical details.
- Highlight APIs, backend architecture, database optimization, production support, deployment, automation, or stakeholder implementation as appropriate.
- Do not present portfolio projects as employment responsibilities.

**Projects**
- Select only projects relevant to the target role.
- Prefer strong implementation evidence over a long list of unrelated projects.
- Include repository links when appropriate.
- Use accurate metrics and explain their context.
- Emphasize architecture, implementation, testing, integration, and deployment where supported.

**Technical skills**
- Group skills into categories.
- Put the most relevant and demonstrated skills first.
- Use JD terminology when accurate.
- Exclude unsupported technologies and irrelevant keywords.
- Distinguish foundational knowledge from hands-on experience where needed.

**ATS compatibility**
- Use a single-column layout.
- Avoid tables, graphics, skill-rating bars, icons, and multi-column layouts in the resume itself.
- Use conventional section headings.
- Keep formatting readable and consistent.
- Avoid keyword stuffing.
- Do not hide text or use invisible keywords.
- Keep the resume concise and scannable.

### Length and Formatting

Default to a **one-page A4 resume** for early-career roles when the relevant evidence fits legibly.

Aim for a well-utilized page without shrinking fonts excessively or adding filler. If a two-page resume is materially more readable and justified by relevant experience, explain why before using that format.

If a LaTeX template is supplied, preserve its useful structure while correcting ATS and readability issues. Otherwise, produce clean, compile-ready LaTeX using a simple professional style.

Use the same factual source across variants, but tailor the headline, summary, skills order, experience bullets, and project selection.

## 13. Phase Eight: Resume-to-JD Validation

After generating each resume, compare it against the corresponding consolidated JD.

Create a validation table:

| Requirement | JD Importance | Resume Evidence | Coverage Status | Recommended Correction |
|---|---|---|---|---|

Use these statuses:

- Clearly demonstrated
- Demonstrated but understated
- Partially covered
- Missing evidence
- Not applicable

Check:

1. Essential skills are represented accurately.
2. Important keywords are included naturally.
3. The strongest relevant experience appears early.
4. Relevant projects are prioritized.
5. Professional experience and projects remain distinct.
6. Metrics are correct and contextually appropriate.
7. The resume does not imply unsupported seniority.
8. The resume remains ATS-readable.
9. No false skills or accomplishments have been introduced.
10. The resume is consistent with the master profile.

If a missing requirement is an actual skill gap, do not insert it into the resume as a claimed competency. Recommend learning, practice, or evidence-building instead.

If a requirement is already supported but poorly presented, improve the wording without changing the underlying facts.

## 15. Phase Ten: Skill-Gap and Interview Preparation Plan

For each primary and secondary target role, produce a prioritized plan.

Classify gaps as:

- **P0 — Blocking:** Mandatory requirements currently unsupported.
- **P1 — High Priority:** Important skills that materially improve role readiness.
- **P2 — Medium Priority:** Useful supporting capabilities.
- **P3 — Optional:** Specialized skills with limited value for current target roles.

For every gap, explain:
- Why employers request it
- What level of proficiency is expected
- Whether I need to learn it or merely demonstrate existing experience better
- A practical project, exercise, or interview topic to address it
- How completion would strengthen my evidence

Avoid recommending that I learn every tool from every JD. Prioritize skills with the greatest cross-role value.

## 17. Final Decision Rule

The purpose of this workflow is not to create the maximum number of resumes or make me appear qualified for every role.

The purpose is to determine:

1. Which roles I can credibly target now.
2. Which roles become more realistic with resume repositioning.
3. Which roles need additional technical evidence or upskilling.
4. Which resume variants offer the greatest useful coverage.
5. How to maximize the strength of my genuine experience and portfolio.

Be rigorous, evidence-driven, and honest.

**Final objective:** Deliver a master resume and a small, strategically selected set of ATS-friendly resume variants, backed by a clear explanation of which roles I should apply for, why I fit them, what gaps remain, and how to improve my competitiveness without inventing experience or achievements.
